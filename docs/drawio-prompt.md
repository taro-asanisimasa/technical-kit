# 他のAIへ渡すdraw.io作図プロンプト

対象資料や既存図を指定し、次の本文を渡してください。Skillの読込に対応しない環境でも使えるよう、単独で読める形にしています。
配置と視覚的な層の根拠・限界は[情報設計の根拠と適用例](../skills/drawio-diagrams/references/information-design.md)にあります。

```text
添付・指定した資料をもとに、draw.ioで編集できる図を作成・修正してください。

位置、余白、まとまり、囲み、接続、視覚的な層からも関係が読み取れる図を求めています。
細かい説明を読む前に全体構造と注目点が分かり、詳しく見ると処理や条件まで追えるようにしてください。

【目的と図の種類】
読者がこの図から何を理解・判断するべきかを決めてください。
図の種類が未指定のシステム・連携・改修の説明では、作図前に、部品、通信の矢印、処理や変更点の注記を使う構成図を望むか1問だけ確認してください。
図の種類が指定済み・確認済み、既存図の限定修正の場合は、再確認せず指定と範囲に従ってください。

【配置とグルーピング】
・一緒に理解・比較する要素は近づけ、異なるまとまりの間には余白を取る。
・同格の要素は形、大きさ、整列をそろえ、意味のある行・列・まとまりを作る。
・単純な関連は、近接や余白による暗黙のグルーピングも使う。
・所属、実行環境、ネットワーク、責任範囲など、区別が必要な境界は囲みや背景領域と短い名前で示す。
・全体と部分の関係がある場合は、入れ子で階層を示す。
・異なる分類軸を、事実と異なる包含関係に押し込めない。
近接、色、囲み、接続が矛盾するまとまりや、誤った所属・順序・経由点を示していないか確認してください。

【見え方として原則2層程度を使う】
次の2層を基本案にし、同じ図の中で読み分けられるようにしてください。
・構造の層：構成要素、役割、所属、境界、全体と部分の関係。
・説明の層：今回注目する経路、処理、条件、変更点、問題箇所と、そのそばの短い説明。

所属の入れ子と、異なる情報の重ね合わせを、どちらも検討してください。
経路図なら構造と通信経路、比較図なら共通構造と差分を重ねる等、目的に応じて役割を決めます。
構造は読める強さを保って控えめにし、線の太さ、明暗、背景領域、余白等で今回の焦点へ視線を導いてください。
色だけに意味を持たせず、必要なラベル、記号、線種も併用してください。
説明は対応する部品や経路の近くに置き、対応箇所を探す負担を減らしてください。

draw.io内部のレイヤー機能を使うかどうかは任意です。
2層は制作上の基本方針で、常に最適と実証された数とは扱わないでください。
単純な図で意味が増えない場合や既存図の限定修正では、層数を満たす追加・再構成をしないでください。
情報が競合して読みにくくなる場合は、強弱や配置を調整するか図を分けてください。

【部品・経路・説明の対応】
資料や実装で確認できた部品を、役割が分かる名前で配置してください。
構成図では、使える場合はサービスのアイコンも使ってください。
通信・操作は矢印でつなぎ、内容を短く書き、接続を始める向きとデータが戻る向きを区別してください。
処理内容、実行条件、変更点は、対応する部品や経路のそばへ置いてください。
到達する経路は実際の処理主体までつなぎ、拒否・遮断される経路は確認できた停止地点で終え、記号や理由を添えてください。
線の束ね方によって、存在しない共有経路、中継処理、経由順序を示唆しないでください。

【比較】
現状と変更案などを比較する場合は、共通要素の位置、囲みの意味、縮尺、表現をできるだけそろえてください。
追加・変更・廃止する部品や経路を、対応する場所で比較できるようにしてください。

【確認と提出】
未確認の要素、接続、境界を、図を整えるために追加しないでください。
事実、提案、未確認事項を区別し、判断を変える条件を見えにくい注記だけへ隠さないでください。

提出前に、次を確認してください。
・縮小しても、全体のまとまりと今回の焦点が分かるか。
・掲載サイズで、名前、矢印、注記を読めるか。
・配置や囲みが、実際とは異なる所属や階層を示していないか。
・始点から終点まで、経路と処理主体を追えるか。
・説明と対象が近く、文字や線が競合していないか。

既存図の修正では、依頼外の内容や手修正を保持してください。
編集可能な元データを残し、画像を出す場合は元データと内容を一致させてください。
XML等の構造の検査と、実際の描画確認を分け、確認できなかった部分は明記してください。
```
