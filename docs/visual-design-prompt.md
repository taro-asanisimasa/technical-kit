# 図・表・画面の見た目を揃える共通プロンプト

HTML/CSS、SVG、draw.io、表、スライドの作成・修正時に、次の本文を渡してください。
目的と役割を共通化し、具体的な値は媒体と既存の設計に合わせます。Skillの読込機能は必要ありません。
draw.ioの編集データ・配線・出力には、[作図プロンプト](drawio-prompt.md)または `drawio-diagrams` を併用できます。
根拠と採用判断は[調査資料](visual-design-research.md)、draw.ioの具体例は[見た目の値と役割](../skills/drawio-diagrams/references/visual-style.md)にあります。

以下はこのキットの指示案です。引用先の公式プロンプトの転載ではなく、特定の値による品質向上を実証したものでもありません。

```text
図・表・画面を、目的と役割に沿った一貫した見た目で作成・修正してください。
必要な情報が読め、同じ役割が同じ見た目になり、視線の順とまとまりが分かることを目標にします。

【適用と優先順位】
・対象の目的、読者、媒体、実際の表示サイズ、変更範囲を最初に確かめる。文脈から決まる事項は再質問しない。
・既存のデザインシステム、テンプレート、凡例、指定された書式を使う。部分修正では依頼外の見た目を作り直さない。
・意味の正確さ、可読性・アクセシビリティ、対象の用途・既存要件を満たした上で、同じ役割の見た目を揃える。
・以下の数値は、新しい技術説明図に既存設定がない場合の初期値。全媒体への絶対規則にはしない。

【目的と視線の順】
・説明図や説明用スライドでは、伝えたいことを1文にし、主に見せたい要素または経路を決める。
・参照表や業務画面では、何を探し、比較し、操作するかを決める。焦点を1つ作るために必要な情報を弱めない。
・関連するものは近づけ、別のまとまりとの間に余白を取る。比較対象の位置・縮尺・表現を揃える。
・配置、囲み、色、接続が、誤った所属・順序・関係を示さないようにする。

【役割と値の対応を先に決める】
・余白、線、面、文字、角丸、強調について、役割名と値を対応させる。
  例：箱の内側=16、同格の箱の間=24、別グループの間=48、通常線=2。
・同じ用途・状態・階層・テーマの要素には、同じ対応を使う。
  候補が16と24だからといって、同じ種類の箱に両方を気分で使い分けない。
・CSS変数、描画用の共通定数、テンプレートの書式など、その媒体で再利用できる形にする。
・値を変える場合は、対象の役割をまとめて変える。意図的な例外は、役割と理由をコメントか設計メモに短く残す。
・この準備や例外の記録のためだけに、利用者への承認待ちや説明用の成果物を増やさない。

【新しい技術説明図の初期値】
・余白・間隔：4 / 8 / 16 / 24 / 32 / 48 / 64 を候補にする。余白なしの0も許可する。
  箱の幅・高さ、中央配置の座標、可変幅、データから求める座標まで、この集合に丸めない。
・線幅：装飾的な枠1、通常の接続線2、主な強調線4を候補にし、矢印の頭も線に合わせる。
  線幅自体が量を表す図ではデータとの対応を優先する。
・角丸：同じ種類の要素で統一し、説明用の箱では8を候補にする。
  円形の記号、入れ子、既存コンポーネントまで同じ角丸へ変えない。
・文字：題28・太字、本文18、必要な場合の注記16を候補にする。
  必要な役割だけを使い、字体・太さ・行間も役割ごとに揃える。
  重要な条件を小さく薄くして収めず、余白・箱の幅・内容の分割を見直す。
・配色：背景 #ffffff、補助の面 #f6f7f8、主文字 #202124、補助文字 #6b7075、
  意味を担う線 #6b7075、装飾的な枠 #d0d3d8、焦点 #3d6fb4、問題 #a94442 を候補にする。
  同じ値を使う役割でも、役割名は分けて管理してよい。
・灰以外は焦点と問題の2色を出発点にする。分類・系列・状態の区別に必要なら役割を追加する。
  色だけに意味を持たせず、ラベル、記号、線種を併用する。
・囲みは同じ役割で表現を揃える。枠と面の併用が所属や境界を伝える場合は許可する。
・この初期スタイルでは、意味を担わない影・グラデーション・装飾を追加しない。
  操作状態や重なりを伝えるUIの表現、指定されたブランド表現は、その用途の設計に従う。

【媒体に合わせる】
・HTML/CSS：既存のトークンとコンポーネントを使い、画面幅や文字の拡大に追従させる。
  操作可能な画面では、必要なフォーカス・選択・読込中・空・エラー等の状態を区別する。
・draw.io / SVG：図の座標単位と掲載倍率を確認し、接続先・ラベル・編集データを保つ。
  図形の移動や見た目の統一によって、実在しない接続や包含を作らない。
・スライド：スライド寸法、閲覧距離、マスターの書式に合わせ、pt等で文字と余白を決める。
  図の28/18をそのまま移さず、投影・配布時のサイズで確認する。
・データ可視化：軸、比率、系列、大小関係を保存する。データの座標を見た目のグリッドへ丸めない。

【表】
・一覧表では「探す鍵 → 判断に効く違い → 補足」を列順の出発点にする。
  時系列、行列、比較軸、既存書式に意味がある場合は、その読み方を優先する。
・比較する数量は右揃え、文字と識別子は左揃えを基本にする。共通の単位は見出しに置く。
・表示用の表では、該当なしは「—」、未確認は「未確認」と区別し、0と混同しない。
  集計・入力用データの空値や数値型を、表示用の文字に置き換えない。
・セルは短い語句か短文を基本にする。長い説明は表の外へ出し、判断に必要な条件は残す。
・HTMLでは表の見出し・行列の対応を保ち、画面配置だけを目的にtableを使わない。

【確認と終了】
1. 意味：内容、関係、数値、比較条件、操作の目的が元資料と一致するか確認する。
2. 値：役割と値の対応、同じ役割の不一致、未定義の直値、例外の理由を確認する。
   許容された値の種類を数えるだけで合格にしない。計算による座標や可変幅は別に扱う。
3. 可読性：実際の背景とのコントラストを確認する。
   Webでは通常本文4.5:1以上、理解に不可欠な図形や操作・状態の識別に必要な表示は3:1以上を確認する。
   装飾だけの枠に同じ基準を一律適用しない。比率を満たしても細線や小文字が読めるか実表示で見る。
4. 描画：提出するファイルや画面を実際に描画し、文字切れ、重なり、不自然な改行、線とラベルの衝突を確認する。
   掲載サイズで読め、縮小しても主なまとまりと視線の順が分かるかを見る。
   ぼかしは強弱を見る補助に限り、題と焦点以外を見えなくすることを目標にしない。
5. 操作・編集：UIでは必要な操作と状態、図やスライドでは必要な編集可能性と元データとの一致を確かめる。
6. 観察した問題を修正し、影響箇所と全体を再確認する。重大な問題が解消したら、好みだけで反復しない。

構造の検査、実際の描画、操作・再編集の確認は分けて扱ってください。
実行できない確認は未実施とし、確認済みの範囲と残る制約を必要な範囲で報告してください。
指示を読んだことや値が揃ったことだけで、見た目や使いやすさの改善を実証したとは扱わないでください。
```

## 使い分け

これは共通の指示本文であり、フォント、描画エンジン、ブラウザ操作、アクセシビリティ検査機能を提供するものではありません。
既存の `generate.py` / `check.py` が上記の配色や値を自動適用・検査する設定でもありません。
媒体と実行環境にある機能で確認し、実行できた範囲を区別します。

初期値を変更した場合は、対象の設定またはテンプレートへ反映してください。
プロジェクト用の設計メモを別ファイルに置く場合は、実際の読込入口から参照し、ファイル名だけで自動読込されると想定しないでください。
