# Technical Docs Kit

技術文書と編集可能なdraw.io図を作成・修正・レビューするためのSkill集です。
入口を文書と図の2つに分け、設計書、出力形式、複雑な図の規則は必要な場合だけ読みます。
計画管理、タスクの終了判定、教材漫画の制作は扱いません。

このキットは指示書とテンプレートです。
文書ファイルを生成するプログラム、画像の描画器、モデル、外部サービスとの接続機能は同梱していません。
利用するAIや編集環境の機能と権限の範囲で使います。

## 2つのSkillと必要時の参照

| 入口 | 担当すること | 必要な場合に読む参照 |
|---|---|---|
| `clear-technical-writing` | 読者に合わせた構成、根拠と条件の扱い、文書の修正・レビュー | 文書の型、設計書の冒頭と対応表、出力形式ごとの確認 |
| `drawio-diagrams` | 根拠に基づく図、編集データ、構造と描画の確認 | 複雑な図の配置、レイヤー、密度、テンプレートの再利用 |

```text
skills/
  clear-technical-writing/
    SKILL.md
    references/
      document-patterns.md
      architecture-documents.md
      output-formats.md
  drawio-diagrams/
    SKILL.md
    references/layout-and-review.md
    assets/
      basic-flow.drawio
      architecture-template.drawio
integrations/
  claude-code/CLAUDE.md.example
  codex/AGENTS.md.example
docs/PUBLICATION.md
LICENSE
NOTICE.md
```

片方のSkillだけでも導入できます。フォルダ内の参照と資材は、そのSkillと一緒にコピーしてください。
もう一方のSkill、特定の業務リポジトリ、個人用設定が存在することは前提にしていません。

## 品質の規則と出力機能を分ける

文書のSkillは、概要と詳細の入口、上位で見える適用条件、根拠の確かさ、図と対応表の役割を扱います。
図のSkillは、実際の関係の確認、目的に応じたテンプレートの複製、編集データの保持、構造検査と描画確認を扱います。
組織やプロジェクト固有の文書契約、命名、保存先、既存テンプレートは、対象側の規約を優先します。

Word、PDF、スライド等を出力する場合は、その環境にある出力機能を使います。
利用できない形式については制約を伝え、利用者が選んだ代替形式で進めます。
このキットの導入だけで、未提供の形式が生成できるようになるわけではありません。

## 導入先を選ぶ

| 利用環境 | 対象プロジェクトだけ | 個人の全プロジェクト |
|---|---|---|
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Codex | `.agents/skills/` | `~/.agents/skills/` |

対象とする範囲を選び、`skills/` 内の必要なSkillフォルダをコピーします。
既存の同名Skillがある場合は比較し、変更前のコピーを保存してから統合してください。
同じSkillを複数箇所へ重ねて導入しないよう、現在の配置も確認します。

共通指示への追記は任意です。
`integrations/` の対応する例を読み、必要な部分だけ既存の `CLAUDE.md` または `AGENTS.md` へ統合します。
これらは指示の全文を置き換えるためのファイルではありません。

Claude Codeで `CLAUDE.md` を新設する場合は、既存の `AGENTS.md` の読込に影響することがあります。
既存指示を維持する方法は [公式の指示読込仕様](https://code.claude.com/docs/en/memory#agents-md) を確認してください。
Skillだけを導入し、共通指示のファイルを追加しない方法も選べます。

Desktopアプリからローカルの配置を使う場合は、ローカル実行のセッションで確認します。
クラウドやSSHでは、その実行先から読める場所へ導入する必要があります。
読込仕様は [Claude Code Skills](https://code.claude.com/docs/en/skills) と [Codex Skills](https://learn.chatgpt.com/docs/build-skills) を参照してください。

## AIに配置を任せる場合

展開したフォルダを読み取れる状態にし、導入対象を指定します。

```text
このキットのREADMEを読み、現在のプロジェクトで利用するAIのSkill配置先へ導入してください。
参照とテンプレートも同梱し、既存の同名Skillがあれば比較してから統合してください。
変更前の内容は別の場所に保存してください。
共通指示へ追記する場合は既存指示の読み込みを維持し、設定や認証、実行権限は変えないでください。
別のプロジェクトや個人全体の配置先は変更しないでください。
最後に、変更したファイルと新しいセッションでの読込確認方法を示してください。
```

## 読込と品質を確認する

新しいセッションで、導入したSkillの名前と `SKILL.md` の実際の読込先を確認します。
短い非機密の資料を指定し、読者、判断したいこと、成果物の形式を伝えて試します。
表示されたSkill名だけで、規則が成果物に反映されたとは判断しません。

設計書では、概要が全体の関係を示し、詳細が対象固有の対応を先に示すかを確認します。
図では、資料と要素・接続が一致し、凡例やラベルから線の意味を理解できるかを確認します。
実装済み、推測、未確認の状態を混ぜず、重要な例外が本文や図の上位で分かるようにします。

ファイルを出力した場合は、提出するファイルそのものを開いて確認します。
draw.ioのXML検査は、文字の収まりや描画の正しさの確認とは別です。
埋込み編集データのある画像では、見える画像と編集データの一致も確認します。
実行・描画していない確認を、成功した確認として報告しないでください。

## 削除する

導入したSkillと、自分で追記した指示部分を削除します。
既存内容へ統合した場合は、保存したコピーと比較して戻してください。
作成済みの文書や図はSkillを削除しても残ります。
