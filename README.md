# Technical Docs Kit

技術文書と編集可能なdraw.io図を作成・修正・レビューするためのSkill集です。
文書の品質には `layered-docs`、図の作成には `drawio-diagrams` を使います。
設計書、出力形式、複雑な図の補足は必要な場合だけ読みます。

指示書とテンプレートに加え、draw.io用の座標計算・検査・簡易プレビュー・編集データ抽出のPythonスクリプトを含みます。
モデル、Word等の文書生成エンジン、draw.io本体、外部サービスとの接続機能は同梱していません。
利用するAIや編集環境の機能と権限の範囲で使います。

## 2つのSkillと必要時の参照

| 入口 | 担当すること | 必要な場合に読む参照 |
|---|---|---|
| `layered-docs` | 読む深さに応じた構成、重要条件と根拠の保持、必要な範囲での修正・レビュー | 設計書の冒頭と対応表、出力形式ごとの確認 |
| `drawio-diagrams` | 根拠に基づく図、配置と視覚的な層、配線、編集データ、構造と描画の確認 | 複雑な図の配置、情報設計の根拠、ツールの入力形式と使い方 |

片方のSkillだけでも導入できます。フォルダ内の参照と資材は、そのSkillと一緒にコピーしてください。
もう一方のSkill、特定の業務リポジトリ、個人用設定が存在することは前提にしていません。

## 品質の規則と出力機能を分ける

`layered-docs` は、本文の基本規範を一式で読みます。
適用範囲、浅い読みでも誤解しない構造、重要条件、根拠、修正・レビューの節度を同じ入口に保っています。
文書の型も本文に含み、補足への案内は末尾にまとめています。
短いチャット返答やコードだけの変更には、文書の型を強制しません。

図のSkillは、実際の関係の確認、目的に応じたテンプレートの複製、編集データの保持、構造検査と描画確認を扱います。
位置・余白・暗黙のグルーピングと所属の入れ子を使い、構造の上に今回の経路・処理・差分を重ねる表現を基本案にします。
見え方は原則2層程度とし、単純な図や限定修正には層数を満たす追加をしません。draw.io内部のレイヤー機能の使用や数は任意です。
方針と研究上の根拠・限界は [情報設計の根拠と適用例](skills/drawio-diagrams/references/information-design.md) を参照してください。
組織やプロジェクト固有の文書契約、命名、保存先、既存テンプレートは、対象側の規約を優先します。

補助スクリプトはPython 3.10以上の標準ライブラリだけで動きます。
新規の反復配置はJSONから生成でき、入れ子の座標、接続位置、直交配線を共通の計算で扱います。
簡易プレビューは外部viewerやサーバーを使いません。PNGの本来の描画には、別途信頼できるdraw.io Desktopが必要です。
使い方と制約は [作図補助ツール](skills/drawio-diagrams/references/tools.md) を参照してください。

新規単発図では、編集データ入りPNGを正本の既定とし、更新は最新の編集データから始めます。
継続生成する図では入力・コードを正本にできます。既存図の方式を優先し、古い生成入力でGUI編集を消さないようにします。

Word、PDF、スライド等を出力する場合は、その環境にある出力機能を使います。
利用できない形式については制約を伝え、利用者が選んだ代替形式で進めます。
このキットの導入だけで、未提供の形式が生成できるようになるわけではありません。

## 導入先を選ぶ

| 利用環境 | 対象プロジェクトだけ | 個人の全プロジェクト |
|---|---|---|
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Codex | `.agents/skills/` | `~/.agents/skills/` |

対象とする範囲を選び、`skills/` 内の必要なSkillフォルダをコピーします。
既存の同名Skillがある場合は比較し、変更前のコピーを保存してから統合してください。
同じSkillを複数箇所へ重ねて導入しないよう、現在の配置も確認します。

共通指示への追記は任意です。
文書と図のSkillに加え、日本語の説明や応答の調子をそろえたい場合は、`integrations/` の対応する例を使います。
必要な部分だけ既存の `CLAUDE.md` または `AGENTS.md` へ統合します。
これらは指示の全文を置き換えるためのファイルではありません。
既存の指示や対象プロジェクトの規約と矛盾する部分は、そのまま追加せず調整してください。

Claude Codeで `CLAUDE.md` を新設する場合は、既存の `AGENTS.md` の読込に影響することがあります。
既存指示を維持する方法は [公式の指示読込仕様](https://code.claude.com/docs/en/memory#agents-md) を確認してください。
Skillだけを導入し、共通指示のファイルを追加しない方法も選べます。

Desktopアプリからローカルの配置を使う場合は、ローカル実行のセッションで確認します。
クラウドやSSHでは、その実行先から読める場所へ導入する必要があります。
読込仕様は [Claude Code Skills](https://code.claude.com/docs/en/skills) と [Codex Skills](https://learn.chatgpt.com/docs/build-skills) を参照してください。

## 以前の文書Skillから更新する

`clear-technical-writing` を導入していた場合は、`layered-docs` を文書の基準にします。
既存の同名Skillと共通指示を比較し、変更前のコピーを導入先の外へ保存してください。
個人で加えた規則は必要なものを維持し、共通指示の参照名も更新します。
読込先を確認できたら、旧 `clear-technical-writing` をSkill探索先から外し、似た規則が重複して選ばれる状態を解消します。
バックアップもSkillとして探索されない場所へ置いてください。

すでに `layered-docs` を使っている場合は、その本文を公開版で一律に上書きしません。
差分を比較し、設計書・出力形式の補足など、必要な追加だけを取り込めます。

## AIに配置を任せる場合

Skillの読込に対応しないAIへ作図を依頼する場合は、[他のAIへ渡す作図プロンプト](docs/drawio-prompt.md)を使えます。
対象資料や既存図を指定し、本文を渡してください。

展開したフォルダを読み取れる状態にし、導入対象を指定します。

```text
このキットのREADMEを読み、現在のプロジェクトで利用するAIのSkill配置先へ導入してください。
参照とテンプレートも同梱し、既存の同名Skillがあれば比較してから統合してください。
変更前の内容は別の場所に保存してください。
旧clear-technical-writingがあれば、個別の変更を維持しながらlayered-docsへ移行し、Skillとして重複しない配置にしてください。
共通指示へ追記する場合は既存指示の読み込みを維持し、設定や認証、実行権限は変えないでください。
別のプロジェクトや個人全体の配置先は変更しないでください。
最後に、変更したファイルと新しいセッションでの読込確認方法を示してください。
```

## 読込と品質を確認する

新しいセッションで、導入したSkillの名前と `SKILL.md` の実際の読込先を確認します。
短い非機密の資料を指定し、読者、判断したいこと、成果物の形式を伝えて試します。
表示されたSkill名だけで、規則が成果物に反映されたとは判断しません。
AIやモデル、共通指示、編集・描画機能が変われば、同じSkillでも成果物は変わり得ます。
指示をそろえることだけで、別環境での品質や使い心地が同一になるとは判断しません。

文書では、見出しや第1階層だけでも結論と重要条件が伝わるかを確認します。
部分修正やレビューでは、依頼範囲を越える改稿や、形式のためだけの指摘を増やしていないかを見ます。

設計書では、概要が全体の関係を示し、詳細が対象固有の対応を先に示すかを確認します。
図では、資料と要素・接続が一致し、凡例やラベルから線の意味を理解できるかを確認します。
実装済み、推測、未確認の状態を混ぜず、重要な例外が本文や図の上位で分かるようにします。

ファイルを出力した場合は、提出するファイルそのものを開いて確認します。
draw.ioのXML検査は、文字の収まりや描画の正しさの確認とは別です。
埋込み編集データのある画像では、見える画像と編集データの一致も確認します。
実行・描画していない確認を、成功した確認として報告しないでください。

## 削除する

導入したSkillと、自分で追記した指示部分を削除します。
既存内容へ統合した場合は、保存したコピーと比較して戻してください。
作成済みの文書や図はSkillを削除しても残ります。
