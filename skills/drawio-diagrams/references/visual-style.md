# 役割と値を対応させて見た目を揃える

新規図で書式のばらつきを抑えるとき、または依頼された範囲で既存図を整えるときに使う。
内容の正確さ、関係の追いやすさ、掲載サイズでの可読性を優先する。
既存の書式や用途に適した記法があればそれを引き継ぐ。
以下は控えめな説明図用の初期案であり、最適な数値や「古く見えない」ことが実証された規則ではない。

## 値の候補と、役割への割当てを分ける

16と24を許可しただけでは、同じ種類の箱に別々の余白が使われる。
描く前に「通常の箱は内側余白16、通常の接続線は幅2」のように対応を決め、同じ役割へ繰り返し適用する。
焦点や状態による変更も、対象ごとの思いつきでなく共通の変更規則にする。
必要な役割だけを定義し、使わない種類や凡例を増やさない。

これらの役割名は設計メモ用であり、生成器の入力JSONへ追加できるキーではない。

## 寸法・文字の初期案

数値はdraw.io上の設定例。書き出し倍率や文書への縮小で、読者が見る大きさは変わる。
先に掲載幅、読む環境、利用できる書体を決める。

| 対象 | 候補と割当て例 | 調整する条件 |
|---|---|---|
| 余白・間隔 | 候補4 / 8 / 16 / 24 / 32 / 48 / 64。通常の箱の内側16、同じ群の間24、群の間48など | 文字、境界、配線が収まる値を役割ごとに選ぶ |
| 線幅 | 装飾的な区切り1、意味を伝える接続線2、焦点の経路4 | 線幅が量を表す図には適用しない。矢印の頭も同種で揃える |
| 角丸 | 同じ種類の箱で同じ設定。角丸なしも選べる | 囲み、部品、注記を一律に同じ形へ変えない。実描画で確認する |
| 文字 | 題28・太字、本文18、注記16を出発点に、必要な役割だけ採用 | 書体、太さ、行間も役割ごとに揃え、掲載サイズで読めるよう調整する |

座標、箱の寸法、接続点まで上記の候補に限定しない。
内容に応じた寸法や中央配置を許し、データの値を表す座標・長さを丸めない。
文字を小さくして詰める前に、文言、配置、図の分割を見直す。
色を薄くする以外にも、配置、余白、太さで主従を示す。

## 色の初期案

| 設計上の役割 | 色 | 用途 |
|---|---|---|
| 通常の面 | `#ffffff` | 箱や背景 |
| 補助的な面 | `#f6f7f8` | まとまりの背景。必要な場所だけ使う |
| 主文字 | `#202124` | 題、部品名、主要な説明 |
| 補助文字 | `#6b7075` | 注記。重要条件を見えなくしない |
| 意味のある線 | `#6b7075` | 接続、境界、理解に必要な記号 |
| 装飾的な区切り | `#d0d3d8` | 消えても意味や所属を失わない補助線 |
| 焦点 | `#3d6fb4` | 今回見る要素や経路 |
| 問題・停止 | `#a94442` | ラベルや停止記号と併用 |

焦点の色と、分類・状態を示す色の役割を混ぜない。
分類色が必要な参照図では、この配色数を守るために必要な区別を消さない。
枠や面は所属・境界などの意味を担う場合に使い、同じ意味には同じ表現を使う。
影やグラデーションはこの初期案では追加しない。既存記法や意味の表現に必要なら理由を残す。

## 実際の背景とのコントラストを確かめる

Webでの目安として、[WCAGの通常文字](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)は4.5:1以上、
[理解に不可欠な非テキスト](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)は隣接色と3:1以上を確認する。
すべての装飾枠に3:1を要求する規則ではない。これだけでスライドや出力画像全体の適合を保証しない。

以下は不透明な単色同士のWCAG式による計算値。表示は小数第3位までの概数で、合否は丸める前の値で判定する。

| 色 | 白との比 | `#f6f7f8`との比 | 判断 |
|---|---:|---:|---|
| `#6b7075` | 5.000:1 | 4.662:1 | この2背景では通常文字にも使える |
| `#3d6fb4` | 5.083:1 | 4.739:1 | この2背景では通常文字にも使える |
| `#a94442` | 5.845:1 | 5.450:1 | 問題を示す文字の候補 |
| `#9aa0a6` | 2.641:1 | 2.462:1 | 理解に必要な線・記号には薄い |
| `#b85450` | 4.749:1 | 4.427:1 | 白では通常文字の基準を満たすが、補助面では届かない |

元の補助文字色を一律に濃くする必要はない。色の用途と背景の組合せで判断する。
背景を変えた場合や、色付きの面へ文字を重ねる場合は再計算し、実出力でも確認する。

## 同梱ツールとの対応

この文書は生成器や検査器の仕様変更ではない。
`generate.py`の既定は経路間隔26、列間104、行間60、`title_height`42、文字18で、独自の役割別配色を使う。
`title_height`はグループの題帯の高さであり、題の文字サイズではない。
配色・線幅・ノード内余白等にはコード内の設定もあり、上記の案は自動適用されない。
`check.py`も、この配色表や余白候補への適合、コントラストを自動検査するものではない。

既存の生成設定を使う場合は、まず[補助ツール](tools.md)に従う。
たとえば`route_spacing`を32に変えるなら、`gap_x`と`gap_y`は両方64以上が必要になる。
GUIやXMLで書式を変更するときも、選んだ正本の運用を守り、古い入力からの再生成で変更を失わないようにする。

## 確認して終了する

1. 役割ごとの値を一覧にし、同じ役割に意図しない差がないか調べる。
2. 候補外の値が必要なら、対象と理由を作業メモや生成元のコメントに短く残して進める。例外だけを理由に承認待ちを追加しない。
3. 構造検査の後、draw.io本来の描画と最終出力を、100%と掲載サイズで見る。文字切れ、重なり、接続先、線の追いやすさを確認する。
4. 縮小やぼかしは、焦点とまとまりを見る補助にする。題と焦点だけを残すために、必要な条件や関係を薄くしない。
5. 意味・表示・再編集が成立したら終了する。描画できなければ、確認済みの構造と未確認の見た目を分けて報告する。

簡易SVGプレビューや値の一致だけを、draw.io本来の描画確認に数えない。
配置と停止条件は[配置とレビュー](layout-and-review.md)、情報構造の根拠は[情報設計](information-design.md)を参照する。
